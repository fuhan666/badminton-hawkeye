# 技术方案

采用本地运行的纯前端应用，场景渲染与视频生成均在浏览器完成。

建议技术栈：TypeScript、React、SVG、Three.js、WebCodecs 和 MP4 封装库。实现围绕球场编辑、三维回放和视频导出组织。

## 数据流

屏幕选点 → 球场坐标 → 落点圆心与归一化来球方向 → 判定与动画 → 预览或逐帧编码 → MP4。

球场尺寸、白线和接触圆共用一份几何数据。来球方向为 `(落点 - 来向点)` 的单位向量。

## 球场与判定

以球网中心为原点，地面为 x/z 平面，高度为 y，单位为米。

尺寸基线：场长 13.40 m，双打宽 6.10 m，单打宽 5.18 m，线宽 0.04 m；前发球线距网 1.98 m，双打后发球线距端线 0.76 m；网柱高 1.55 m，网中央高 1.524 m。实现时核实标准尺寸的测量基准，按外边界绘制边线。

有效矩形：`x ∈ [-W/2, W/2]`，`z ∈ [-6.7, 6.7]`。求圆心 P 在矩形上的最近点 C，`|P-C|² ≤ r²` 为 IN，否则为 OUT。该方法同时覆盖边线和角落。

SVG 负责全场选点和局部精调；通过坐标变换保持缩放前后的落点一致。

## 三维回放

用 `evaluateReplay(input, time)` 统一计算球的位置、朝向、镜头和结果显示。相同输入与时间产生相同画面，预览和导出共用这一逻辑。

用参数曲线生成固定风格球路，朝向跟随曲线切线，终点对齐球托底端。跨网路径保留合理高度。白线使用清晰的几何面，最终圆形印记与编辑器共享尺寸。

分镜围绕飞行和落地关系构图，分别覆盖边线、角落和远离边界的位置。结果文字绘入导出画面。

## 视频导出

先用最小回放验证目标浏览器的 WebCodecs 编码和 MP4 封装。封装库按维护情况、许可证和接入成本选择。

按 `t = 帧序号 / 帧率` 逐帧渲染与编码。导出时固定输入和分辨率，显示进度并支持取消；完成编码后生成本地下载文件，结束时释放帧与编码资源。不支持当前编码时清楚提示用户。

## 验证与交付

重点测试圆与矩形相交、相切、角落、赛制切换、坐标转换和方向一致性。用代表性样片检查构图与触地效果，实际播放导出文件验证时长和画面。
